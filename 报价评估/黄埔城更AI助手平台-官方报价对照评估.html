01

核心判断

五条判断按重要性排序，前三条直接影响签约与交付边界。

  • 价格本身站得住，且利润垫厚。报价 23 个收费科目的小计、占比经逐格复算全部勾稽正确（282＋8＝290 万）。按内部成本估算 v4.5 的人天体系换算到 MaaS 口径，基准成本约 107 万，即使人天超支 25%（悲观档约 133 万）毛利率仍有 54%。
  • 范围存在实质性不对等，这是最大风险。报价标的是"黄埔城更 AI 助手平台"——B-03 要按商务/工程/安全/财务多个业务域打包建设首批助手（43 万，清单"需求确认后定"）；而 docs 设计的是"RAG 利润智能系统"：六因子利润推演引擎、数值对账铁律是灵魂，却在报价单 23 个科目中没有任何独立对应项。两边都需要向中间靠。
  • 10 亿 Token 额度在重 RAG 场景下偏紧，且超额口径是开口的。docs 自述每问上下文 2–5 万 Token；此口径下 10 亿 Token 仅够 30 人每人每天约 3–9 问。报价只写"超出另行协商"，没有单价、没有第二年续费价。
  • docs 并存三代架构口径，签约后必须统一。PRD v1 / 1pager / 部署文档仍是"双卡 RTX 6000 本地 GPU"，成本估算 v4.5 已改为"云租 AutoDL 单卡"，报价 v0.4 则是"集团 MaaS、不含任何自建推理 GPU"。若按报价履约，前两份方案的架构章、硬件 BOM、风险登记册均需改版。
  • 官方承诺的"培训 / 用户文档"在内部估算中没有工作包。报价每个科目备注均含"实施联调、培训与验收配合"，报价说明另承诺约定场次培训与操作文档；成本估算 356 人天中联调、验收有覆盖，但培训和用户操作文档为零，约缺 4–7 人天（1.2–2.1 万）。

10 亿 Token 额度够不够：情景测算

口径：30 人 × 250 个工作日；每问 Token 数取 docs 自述的 RAG 上下文 2–5 万（系统提示＋检索片段＋多轮历史＋输出），测算取 3 万/问的中性值。

不同使用强度下的年 Token 消耗

红线＝首年赠送额度 10 亿；每人每天 5 问即已触线，10 问超额约 1.25 倍。

反推：10 亿额度对应每人每天可问数

每问消耗可问/人/天判断
1.5 万 Token（轻量短问答）≈ 8.9 问基本够
3 万 Token（多轮＋知识库片段）≈ 4.4 问偏紧
5 万 Token（长文档/多片段）≈ 2.7 问不够
另一个参照系：docs 成本估算路线 D 按全系统 50 问/天估月费 30–250 元——那是演示期个位数用户口径；30 人正式上线后提问量通常增长一个数量级。按公有云零售价（qwen-plus 输入 0.8 元/输出 2 元每百万 Token）10 亿 Token 仅值约千元级，真正的风险不是钱，而是额度管控与超额单价不透明。
签约前应写入合同的 Token 条款：①超额部分单价与计费方式（不能只写"另行协商"）；②"约 30 人"是注册人数还是并发账号，扩容怎么收费；③Embedding/Rerank/文档理解是否共享该额度；④第二年起的续费价格与调价机制；⑤额度用尽时是熔断停服还是按量续通。

P2

报价明确不含"甲方机房基建、信创换卡差额"，docs 也完全未考虑信创。政企/区属项目信创是常见后续要求，可作为二期增项，但需在首轮沟通留痕。服务器落位机房（供电/机柜）同样需甲方落实。

处置：列入"不含范围"确认单，避免默认承担。
P2
