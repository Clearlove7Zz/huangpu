> v2 变更：模型推理走**集团 MaaS**（出站 HTTPS），目标机**无 GPU**；新增 MaaS 接入配置（§三·MaaS）、平台库 PostgreSQL（5433）部署与备份、出站白名单与额度熔断运维；自托管 vLLM 双卡部署降为备选（见架构附录 H，本文不再包含）。

覆盖四种场景：本机开发、局域网演示、目标机部署、常见坑。所有命令均在仓库根目录执行（另注明者除外）。

## 前置要求

| 组件 | 版本 | 用途 |

| Docker Desktop / Docker Engine | 任意近期版 | WeKnora 全套容器＋平台库 PG |
| Node.js | ≥ 18 | 网关 + 引擎 MCP（零 npm 依赖）+ 前端构建 |

## 一、本机开发

```bash
# 1. WeKnora 后端（首次需先按 README「WeKnora 后端」克隆）
cd weknora-local
docker compose up -d                    # 六件套：ui/app/docreader/postgres/redis/neo4j
# 验证：http://localhost 可登录即 OK

# 2. 引擎 MCP 与网关（两个终端，或 nohup）
cd huangpu-gateway/engine-mcp && node server.mjs    # :18095
cd huangpu-gateway && node server.mjs               # :8090
# 验证：curl http://127.0.0.1:8090/health

# 3. 前端
cd huangpu-react
npm install --legacy-peer-deps
npm run dev                              # http://localhost:5173
```

`.env` 约定：`weknora-local/.env`（沙箱开关/代理/数据库密码）、`huangpu-gateway/.env`
（`WEKNORA_API_KEY`，上游 401 时检查这里）。两文件均不入库，模板见各自 `.env.example`。

> MaaS 开发期：在 `weknora-local/.env` / builtin_models 配置 MaaS 基址与密钥（见 §三·MaaS）；
> 尚未开通时可先用任意 OpenAI 兼容端点（演示期已验证），端点可配置切换，代码不写死。

## 二、局域网演示（同事同网段访问）

```bash
# 前端放开监听
cd huangpu-react && npm run dev -- --host 0.0.0.0
# 防火墙放行（管理员 PowerShell；或首次启动时在弹窗点"允许"）
netsh advfirewall firewall add rule name="vite-5173-lan" dir=in action=allow protocol=tcp localport=5173
netsh advfirewall firewall add rule name="weknora-80-8080-lan" dir=in action=allow protocol=tcp localport=80,8080
ipconfig    # 查本机 IPv4
```

同事访问 `http://<本机IP>:5173`（数字沙盘）与 `http://<本机IP>`（WeKnora 完整版）。
Docker 端口映射默认绑 0.0.0.0，无需额外配置。
注意：WLAN 为"公用网络"档时入站默认拒，规则必须显式加。
外网/跨网段备选：`cloudflared tunnel --url http://localhost:5173` 生成临时公网地址。

## 三、目标机部署（Linux 服务器）

### 方式 A：从源码部署（推荐）

```bash
git clone https://github.com/Clearlove7Zz/huangpu.git
cd huangpu
git checkout huangpu-react && npm ci --legacy-peer-deps && npm run build   # 前端产物 dist/
git checkout master
git clone https://github.com/Tencent/WeKnora.git weknora-local            # 后端按官方仓库部署
cd weknora-local && cp .env.example .env && docker compose up -d
```

前端 dist 用 nginx 托管，`/api` 反代网关 8090：

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
    location /api/ { proxy_pass http://127.0.0.1:8090; proxy_set_header Host $host; proxy_read_timeout 300s; }
}
```

### 方式 B：镜像整包迁移（内网/无外网目标机）

在开发机导出、目标机导入（镜像约 12GB，需 exFAT/ntfs 移动盘或分卷传输）：

```bash
# 开发机
docker save wechatopenai/weknora-ui:latest wechatopenai/weknora-app:latest \
  wechatopenai/weknora-docreader:latest wechatopenai/weknora-sandbox:latest \
  paradedb/paradedb:v0.22.2-pg17 redis:7.0-alpine neo4j:2025.10.1 | gzip > images.tgz
docker exec WeKnora-postgres pg_dumpall -U postgres | gzip > pg.sql.gz
docker run --rm -v weknora-local_data-files:/src:ro -v $PWD:/out alpine tar czf /out/data-files.tgz -C /src .

# 目标机
docker load -i images.tgz
docker volume create weknora-local_data-files
docker run --rm -v weknora-local_data-files:/dst -v $PWD:/src:ro alpine sh -c 'cd /dst && tar xzf /src/data-files.tgz'
cd weknora-local && docker compose up -d postgres
docker exec -i WeKnora-postgres psql -U postgres -d postgres < ../pg.sql.gz   # 注意解压
docker compose up -d
```

目标机要求（v2，报价 H-01）：Linux x86_64、Docker + Compose v2、**CPU 16–32 核、内存 64–128GB（跑全套容器＋Neo4j＋bge/docreader CPU 兜底建议偏上限）、SSD 1–2TB（建议 RAID1）、无 GPU**；配 UPS 与备份存储（H-02）。

### MaaS 接入配置（v2 新增，M0 完成）

1. **出站白名单**：机房防火墙/代理仅放行集团 MaaS 基址的 HTTPS（443）出站；其余外网约闭。手机端另需公网入站域名（备案＋SSL），暴露面书面批准。
2. **密钥与环境变量**（服务端持有，不进前端、不入库 git）：

```bash
# weknora-local/.env 或 builtin_models.yaml 引用
MAAS_BASE_URL=https://<集团MaaS基址>/v1
MAAS_API_KEY=<M0 下发，按环境区分>
MAAS_MODEL_CHAT=<对话模型，以接口清单为准>
MAAS_MODEL_EMBED=<embedding 模型；缺失则指向本地 bge-m3:11434>
MAAS_MODEL_RERANK=<rerank 模型；缺失则指向本地 rerank:8001>
# 网关 .env 追加
MAAS_QUOTA_ANNUAL=10000000000   # 年度额度（约10亿，以合同为准）
MAAS_QUOTA_WARN=0.70,0.90,1.00  # 阈值（架构 §4.7）
```

3. **槽位注册**：WeKnora 后台/`builtin_models.yaml` 以 OpenAI 兼容 generic provider 注册四槽位（LLM/Embedding/Rerank/文档理解）；MaaS 不具备的槽位接 CPU 兜底容器（bge-m3 走 Ollama :11434、reranker 走仓库 `rerank_server_demo.py` :8001、文档解析用内置 docreader）。
4. **联调验收**：四类能力各跑通；回填真实首字延迟/并发/每问 Token（直答/工具链/长上下文各采样，架构 §4.7 额度测算）；验证备用端点切换与额度熔断（③/③'级）。

### 平台库 PostgreSQL（v2 新增，M2）

网关自有独立 PG 实例（与 WeKnora PG 5432 隔离，规划端口 **5433**），三 schema：iam（账号/角色/会话/登录审计）、biz（台账/基线快照/接入任务/同步日志）、ops（maas_usage/quota_budget/审计入库）；建表脚本与字段见《数据结构设计》。容器纳入同一 Compose 编排或独立 compose，数据卷纳入 §五备份。

## 四、常见坑（均实测踩过）

| 坑 | 处置 |
|---|---|
| WeKnora app 反复 `lookup neo4j: no such host` | neo4j 容器没起：`docker compose up -d neo4j`，app 会自动恢复 |
| docreader gRPC EOF | Docker Desktop 注入系统代理所致；`NO_PROXY` 必须含 `docreader` 等内部服务名（.env 与 compose 有交互，见 weknora-local/.env 注释） |
| 容器构建连不上国内 apt 源 | 构建容器继承 Clash 代理：`docker compose build --build-arg http_proxy= --build-arg https_proxy= --build-arg no_proxy=* ...`；docreader 的 `APT_MIRROR` 须带 `http://` 协议头 |
| 前端 Dockerfile 只 COPY dist | 改 WeKnora 前端后须先 `scripts/build_frontend_dist.sh` 再 build，否则镜像里是旧产物 |
| npm 装不上 | huangpu-react 用 `--legacy-peer-deps` |
| 上游 401 | 网关 `.env` 的 `WEKNORA_API_KEY` 与 WeKnora 侧不一致或为空 |
| 问答显示"本地演示引擎" | 网关或 WeKnora 未启动的正常降级；查 `:8090/health` 与容器状态 |
| MaaS 连接超时/403（v2） | 出站白名单未放通 MaaS 基址 443、密钥错误或模型名与接口清单不符；查防火墙、`MAAS_*` 变量与槽位配置；网关自动切备用端点并亮"备用模型"徽章 |
| MaaS 不提供 Embedding/Rerank/文档理解（v2） | 对应槽位切 CPU 兜底（:11434/:8001/docreader），M0 接口清单确认后即配置，不留空槽位 |
| 额度熔断红色横幅（v2） | 周期用量达 100% 的正常③'级保护：生成式禁用、检索与引擎数值保留；查 maas_usage 与续通审批，勿重启绕过 |
| 平台库连不上（v2） | 5433 容器/数据卷未起或端口与 WeKnora PG 5432 冲突；查 compose 与《数据结构设计》连接串 |

## 五、数据备份

```bash
# 数据库全量（建议每周）——WeKnora 库 5432
docker exec WeKnora-postgres pg_dumpall -U postgres | gzip > backups/pg-$(date +%F).sql.gz
# 平台库 5433（v2，iam/biz/ops；含账号、台账基线、用量审计）
docker exec platform-pg pg_dumpall -U postgres | gzip > backups/platform-pg-$(date +%F).sql.gz
# 知识库文件卷
docker run --rm -v weknora-local_data-files:/src:ro -v $PWD/backups:/out alpine tar czf /out/data-files-$(date +%F).tgz -C /src .
```

备份策略（报价 F-03）：平台库与知识库每周全量＋每日增量（WAL 或 pg_dump 自定义格式），备份至 H-02 备份存储并定期恢复演练（恢复时长目标见 PRD 验收）；台账基线快照（baseline_snapshot）不可变，删除传播遵循《数据结构设计》§3。

回退：WeKnora 镜像层回退用 `git tag backup/pre-rebase-20260903` 重建；数据库回退直接导入最近备份（迁移单向，不可降版本直启）。
