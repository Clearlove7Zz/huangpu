## 1. 总体架构

平台由七部分组成：React 电脑端、手机端（小程序推荐/H5 备选，管理层速查，实施前确认）、Node 后端网关（认证/RBAC/对账/审计/**Token 计量**）、WeKnora RAG 编排（Go）、推演引擎 MCP（Node，数值单源）、平台库 PostgreSQL（账号/登录态＋业务台账/引擎基线，网关自有）、**集团 MaaS 模型服务（对话/文档理解/Embedding/Rerank 的 OpenAI 兼容 API，首年约 10 亿 Token 额度）**。

**数据边界（2026-09-20 按报价 v0.4 修订）**：知识库文档、台账、向量索引、知识图谱、账号与审计数据**全部留在内网应用服务器**；出内网的只有两类——①发往集团 MaaS 的请求（提示词＋检索上下文片段＋模型返回），②手机端经公网 HTTPS 对网关的访问。MaaS 不存业务数据、不持有内网凭据。MaaS 不可用或额度用尽时的降级见 §4.5。

【现状】端到端链路（演示形态，已逐位验证）：

```
客户端：浏览器(huangpu-react) ／ 手机端（小程序推荐/H5 备选，管理层速查，实施前确认）
   │  /api/v1/*（HMAC 令牌；手机端经公网 HTTPS）
   ▼
后端网关(:8090, Node) ── 认证 / 角色RBAC / 输出对账 / Token 计量与额度管控 / 审计
   │ 平台库 PostgreSQL（独立容器，网关自有：账号·登录态 schema ＋ 业务台账·引擎基线 schema）
   │ 注入 X-API-Key（WeKnora key 只存网关；MaaS key 同样只存网关）
   ▼
WeKnora(:8080, Go+gin, Docker) ── PostgreSQL 17 + pgvector / Redis 7 + asynq / Neo4j 图谱
   │ ① 模型调用（OpenAI 兼容接口，出站 HTTPS）  ② MCP 工具调用（http-streamable）
   ▼                                              ▼
集团 MaaS（对话/文档理解/Embedding/Rerank）   推演引擎 MCP(:18095, Node，内网)
   └ 首年约 10 亿 Token 额度（报价 C-01），网关侧计量、阈值告警、超额熔断
```

算力与部署职责（2026-09-20 按报价 v0.4：集团 MaaS 主口径，本地仅一台应用服务器）：

| 位置 | 承载 | 说明 |
|---|---|---|
| 集团 MaaS（报价 C-01，首年约 10 亿 Token、约 30 人场景） | LLM 对话、文档理解（OCR）；Embedding/Rerank 以 MaaS 接口清单为准（不具备时本地 CPU 兜底，见下） | OpenAI 兼容端点，WeKnora 四槽位配置级接入、零改码；不含自建推理 GPU；仅提示词与检索上下文出内网；额度由网关计量（§4.7） |
| 应用服务器（本地，报价 H-01 建议 16–32 核 / 64–128GB / SSD 1–2TB） | WeKnora 全套容器（含 Neo4j）、后端网关、推演引擎 MCP、平台库 PostgreSQL（账号＋台账）、前端静态托管、Cube 沙箱 | 无 GPU 依赖；bge-m3（约 1.2GB）/reranker（约 1.2GB）必要时 CPU 推理兜底；docreader CPU 解析兜底；知识库/台账/向量/图谱/审计全部在本机 |
| 手机端接入（报价 A-02） | 公网 HTTPS 域名（备案＋SSL）反向代理到网关 | 形态小程序或 H5，实施前确认（见《UI 与功能设计》§1、成本估算 §6.5） |

设计原则（后端架构的五个不变量）：

1. **数值铁律**：利润/进度/现金流数值 100% 由确定性引擎计算，大模型只做理解和表述，禁止自算。
2. **权限强制在服务端**：前端 `rbac.ts` 只做界面过滤（可被篡改），知识库/智能体/利润权限的真实拦截在网关。
3. **数据内网、模型上移**（2026-09-20 按报价 v0.4 修订）：知识库、台账、向量、图谱、账号与审计数据全部本地；模型能力统一走集团 MaaS API，出内网的只有提示词与检索上下文（MaaS 为集团内合规通道，开通仍需负责人批准数据口径）；MaaS 不具备的 Embedding/Rerank/文档解析由本地 CPU 兜底。
4. **环境硬分界**：纯演示允许 Docker/本地进程；研发、测试、生产一律 Cube 沙箱。
5. **额度可观测、超额有闸**（v2.0 新增，对应报价 C-03）：所有发往 MaaS 的调用经网关计量（Token 入/出、调用方 user_id、助手/知识库），月度预算阈值告警，超额默认熔断到"只读知识库＋本地引擎"模式，续通需人工审批（§4.7）。

## 4. 核心机制

### 4.1 数值铁律与引擎单源

`huangpu-gateway/lib/engine.mjs` 是利润算法的唯一实现：六因子（`FACTORS`/`defaultFactors`）、基线（`getBaseline`）、情景推演（`simulate`）、挣值计算（`calcEarnedValue`）、预设情景（`PRESETS`）；数据常量（利润红线 16.66、现金流等）独立在 `lib/engine-data.mjs`。

两个服务端消费方 import 同一份代码：engine-mcp 的工具层（`engine-mcp/server.mjs` L15-16）与网关兜底出数（`lib/reconcile.mjs`），保证零漂移。前端另有一套读 mock 数据的本地降级实现（`src/utils/answer-engine.ts`、`decision-engine.ts`），属演示脚手架，生产降级路径以网关兜底为准。

### 4.2 输出对账（网关强制）

- 对账白名单【现状】只认 4 个引擎工具的调用记录：`run_scenario`、`get_baseline`、`get_current_status`、`list_presets`（`lib/reconcile.mjs` 的 `ENGINE_TOOL_RE`）。`knowledge_search` 命中不算。
- 图谱查询纳入白名单【目标】：Neo4j 图谱检索作为第 5 个可识别的数据工具调用计入对账，命中可佐证回答具有数据来源；对账仍不比对数字内容，数值铁律不变——图谱提供关系与上下文，确定性数值仍以引擎为唯一来源。
- 三值裁决：**pass**（含数字回答有引擎调用记录）/ **reject**（含数字但无引擎调用，判定模型编造——拒收回答并退回引擎兜底出数）/ **na**（不含数字的回答）。
- 裁决结果以 SSE 事件 `gateway_audit` 回传前端展示横幅；reject 时该事件携带网关用引擎重算的完整答案（`formatEngineAnswer`），前端以分隔线追加在原回答之后——原回答不移除，对账只判流程完整性、不比对数字内容，数字内容正确性由评测集逐位比对把关。
- 演示链路已做逐位验证：问"新联01利润率"，引擎输出 19.59→18.46，AI 回答数字与引擎结果逐位一致。

### 4.3 认证与角色权限

- 登录签发 HMAC-SHA256 令牌（12h）；`/api/v1/*` 一律验令牌（`lib/auth.mjs`）。小程序端经微信授权登录换取网关令牌（登录态映射），RBAC 三约束复用同一套服务端拦截。
- 服务端 RBAC（`lib/rbac.mjs`）覆盖 **6 个业务角色 + 1 个全权限测试账号**，每个角色约束三件事：
  - 可检索知识库（`kbKeywords` 白名单，如指挥长仅"项目/现金流"两库，商务部 `*` 全库）；
  - 可用智能体（内置智能体按 ID 白名单；自定义智能体按名称关键词匹配——因 WeKnora 生成的智能体 ID 在知识库重建后会漂移）；
  - 能否问利润（`canAskProfit`）：安全员为 `false`，利润问题在网关直接 403。
- 未识别角色落入 FALLBACK 最低权限（最低权限智能体 + 不可问利润）。
- API key 边界（源码核实）：WeKnora 的 tenant API key 只能限定知识库范围（`TenantAPIKey.KnowledgeBaseIDs`，`internal/types/tenant_api_key.go`），**限不了会话使用哪个 Agent**。因此浏览器不持 WeKnora key：key 只存网关 `.env`，每次上游调用由网关注入 `X-API-Key`；Agent 级白名单由网关强制。

### 4.4 MCP 集成

- 引擎侧（engine-mcp）：Streamable HTTP 无状态传输、`/mcp` 路径、`X-API-Key` 自鉴权、bind 0.0.0.0:18095；4 个工具 `run_scenario`（利润情景推演）、`get_baseline`（地块基线指标）、`get_current_status`（现状诊断）、`list_presets`（预设情景）。
- WeKnora 侧：`MCPManager` 管理连接（`internal/mcp/manager.go`），`mcp_services` 表持久化配置（transport_type/url/headers/auth_config，JSONB，`migrations/000001_agent.up.sql` L263-280）；MCP 工具注册进 Agent 工具列表，Agent 对话中按需调用。
- 网络放行：WeKnora 容器经 `host.docker.internal:18095` 访问宿主机引擎，SSRF 白名单与 `NO_PROXY` 已配置（`weknora-local/.env` L718-754）。

### 4.5 降级链（MaaS 主口径，2026-09-20 修订）

| 级别 | 故障 | 降级行为 | 实现位置【现状】 |
|---|---|---|---|
| ①正常 | MaaS、WeKnora、引擎均可用 | MaaS 对话/理解 → 引擎 MCP 取数 → 网关对账 → SSE | 全链路 |
| ②引擎不可用/对账 reject | 推演引擎 MCP 超时或裁决 reject | 网关 `formatEngineAnswer` 本地出数（与 MCP 同源零漂移），数值仍为确定性结果 | `lib/reconcile.mjs` L37-80 |
| ③MaaS 不可用（服务故障/网络不通） | LLM 槽位故障 | 按预案切换备用 OpenAI 兼容端点（集团备用区或公有云 qwen 系列，需书面批准、费用走小额 API 科目）；WeKnora 槽位为配置项，切换不改码 | 演示期以 mimo-v2.5 验证过该通路；WeKnora 模型配置 |
| ③'额度异常 | Token 用尽/超额未续 | 网关熔断到"只读知识库检索＋本地引擎出数"模式：停止生成式回答，保留检索列表、数值问答与台账查询；页面显式额度提示；审批续通后恢复（§4.7） | 【目标】网关额度中间件 |
| ④RAG 整体不可用 | WeKnora 容器崩溃 | 前端 `ragReady()=false`，走本地演示引擎（读 mock，仅演示形态）；生产形态由网关返回 503 与维护页 | `chat-service.ts` L71-141 |
| 备选 R-B | MaaS 长期不可用/数据口径不批准 | 启用自托管 vLLM（云租 96GB 单卡或本地 GPU），WeKnora 四槽位改指向自建端点；需负责人书面批准与预算追加 | 附录 H |

**不变原则**：任何降级级别下，数值仍由确定性引擎产出，绝不退化为大模型自算；RBAC 与对账在所有级别生效；每次降级切换留痕（user_id/时间/原因/恢复时间）。

### 4.6 审计

网关以 JSONL 落 `logs/gateway-audit.jsonl`（`server.mjs` L53-61），覆盖登录、代理调用、对账裁决。目标形态要求可追溯"谁、何时、问了什么、调了哪些工具、对账结论"；WeKnora 侧沿用其会话记录。

### 4.7 Token 计量与额度管控（v2.0 新增，对应报价 C-01/C-03）

MaaS 首年赠送约 10 亿 Token（约 30 人场景），超额部分报价仅约定"另行协商"。额度是开口合同风险，必须在网关侧做成可观测、可告警、可熔断的机制，而不是等账单到来。

**计量口径**：

- 计量点设在网关（浏览器/手机端不直连 MaaS，所有模型调用经 WeKnora→MaaS，网关在 SSE 旁路同时取得 WeKnora 用量回执 usage 字段：prompt_tokens / completion_tokens / model）。
- 每次调用落一条用量记录（user_id、角色、助手/智能体 ID、知识库范围、入/出 Token、模型、时间、会话 ID），结构见《数据结构设计》§6 `maas_usage`。
- Embedding/Rerank/文档理解若共享额度，按 MaaS 回执口径一并计量；若独立计费则分列 [NEED：M0 前随接口清单确认]。

**阈值与动作**（阈值为初始建议，运营一个月后按真实日志校准）：

| 用量水位（月度/年度双口径） | 系统动作 | 用户可见 |
|---|---|---|
| ≤70% | 正常 | 个人菜单中显示本部门用量 |
| 70–90% | 网关向管理员告警（消息/邮件） | 管理员页黄色预警 |
| 90–100% | 逐日推送；新增长上下文/批量任务提示管理员审批 | 橙色预警 |
| 达到/超过年度额度 | 默认熔断生成式调用，保留检索、数值问答、台账查询（③'级降级） | 红色横幅＋"额度待续" |
| 审批续通后 | 恢复生成式调用，超额按合同单价单列结算 | 横幅解除 |

**容量参考（情景测算，非承诺值）**：按 RAG 每问 2–5 万 Token（系统提示＋检索片段＋多轮历史＋输出），10 亿 Token/年 ÷ 30 人 ÷ 250 工作日 ≈ 每人每天 2.7–8.9 问（3 万/问时约 4.4 问）。M0 上线后须以真实问答日志回归本测算，并在 M2 评审给出"额度是否够用一年"的结论；不够用时三条出路：①压缩检索片段与多轮历史（上下文预算管理）；②合同追加额度包；③对高频场景启用备选 R-B 自托管。
