# AI 问答页 Orbs 风格重设计规格

## 目标

在不改变系统左侧导航、权限模型和其他页面的前提下，将 `AiAssistant` 重做为浅色、极简、沉浸式 AI 工作台。视觉借鉴 Orbs 的状态胶囊、点阵思考核心和克制动效，业务能力保留并扩展为：

- 按角色权限选择智能体
- 按角色权限选择检索文件夹（WeKnora 知识库）
- 默认勾选当前角色有权限的全部文件夹
- 上传附件作为当前问题的临时上下文
- 保留流式回答、RAG 进度、引用抽屉、会话持久化

## 视觉方向

- 页面继续使用 Codex 浅色主题，不引入 AI 页独立深色主题
- 去掉大面积中后台卡片和厚重边框，使用留白、细分隔线和浅色胶囊
- 欢迎状态居中显示动态点阵核心，旁边显示“城建利润助手”与连接状态
- 快捷问题使用轻量圆角胶囊，两列布局在窄屏下改为单列
- 对话内容采用文档式排版：用户问题右对齐或弱色块，AI 回答左对齐，不使用高对比气泡
- 输入区固定在内容底部，使用单个悬浮白色工作台；附件预览在输入区上方显示
- 所有动效支持 `prefers-reduced-motion: reduce`

## 页面结构

保留应用外层布局和左侧导航。AI 页面内部由四部分组成：

1. 顶部轻量标题区：助手名称、在线状态、当前会话操作。
2. 空状态欢迎区：点阵核心、欢迎文案、快捷问题。
3. 对话区：用户问题、AI 回答、流式状态和引用。
4. 底部输入工作台：多行输入、附件预览、智能体选择、文件夹选择、发送/停止。

有消息后，欢迎区收缩为页面顶部的小型状态核心，避免占用回答空间。会话列表仍由现有页面侧栏提供，不在 AI 内容区重复实现。

## 智能体选择

沿用 `src/config/rbac.ts` 和 `filterAgentsByRole`：

- 只展示当前角色允许的智能体。
- 默认选择 `getRbac(role).defaultAgentId`。
- 选择器显示名称和简短能力说明，不显示未授权智能体。
- 智能体变更只影响下一次提问，不修改历史消息。
- 发送请求时将选中的 `agentId` 传入 `chatWithRag`。

## 文件夹选择

文件夹是前端对 WeKnora 知识库的业务名称：

- 只展示 `filterKbsByRole(role, kbs)` 返回的知识库。
- 默认选择全部有权限的知识库。
- 选择器支持多选、全选、清空和显示已选数量。
- 清空后允许发送，表示本次不检索知识库；服务层不得偷偷回退到全局知识库。
- 选择结果只影响下一次提问，并保存到当前页面状态，不写入其他用户或角色。
- 请求时将所选 ID 传为 `knowledge_base_ids`。

选择器可以采用截图中 `@` 按钮的轻量浮层，但第一版只实现“文件夹”入口，暂不实现标签和单文件提及。

## 附件能力

WeKnora 当前已提供临时附件接口：

- `POST /api/v1/sessions/{sessionId}/attachments`，multipart 字段为 `file`，可附带 `agent_id`、`agent_source_tenant_id`、`parser_engine=auto`。
- `GET /api/v1/sessions/{sessionId}/attachments/{attachmentId}`，用于轮询解析状态。
- `GET /api/v1/sessions/{sessionId}/attachments/{attachmentId}/preview`，用于预览。
- `DELETE /api/v1/sessions/{sessionId}/attachments/{attachmentId}`，用于移除或清理。
- 对话请求使用 `attachment_ids` 传入已上传附件。WeKnora 也支持 `attachment_uploads` 的 base64 兼容路径，但认证 Web 客户端优先使用临时附件 ID。

附件处理规则：

- 支持文档、表格、演示文稿、文本、图片和音频，具体类型由后端解析器能力决定。
- 默认最多 5 个附件，沿用 WeKnora 当前上传组件的大小和扩展名校验策略。
- 选择文件后立即创建临时附件并显示上传进度、解析中、完成、失败状态。
- 只有状态不是 `failed` 的附件才能随问题发送；解析仍在进行时由 WeKnora 后端等待或报告流水线状态。
- 发送成功后保留附件元数据在用户消息中；用户主动删除时调用 DELETE。
- 页面卸载或会话删除时清理未发送附件，避免临时文件堆积。
- 附件只作为当前会话上下文，不自动写入永久知识库。若未来需要入库，另做明确的“上传到文件夹”流程。

由于当前本地前端只在发送时由 `streamKnowledgeChat` 创建远端会话，而附件上传要求先拥有 `sessionId`，服务层需要增加“创建/确保远端会话”的能力：发送带附件的问题时先创建远端会话，上传并等待附件进入可用状态，再发起流式问答；无附件时保留现有懒创建行为。

## RAG 状态表现

替换当前大块 `RagPipeline` 卡片为轻量 Orbs 风格状态组件：

- 空闲：`准备回答`，小型静态或低频呼吸点阵。
- 理解：`理解问题`。
- 检索：`检索文件夹`，显示已选文件夹数量。
- 附件解析：`读取附件`，显示解析进度或状态。
- 重排：`整理证据`。
- 生成：`生成回答`，点阵核心进入工作状态。
- 完成：状态胶囊收起，回答正文成为主视觉。

状态仍由现有 SSE 的 `tool_call`、`references`、`answer`、`onDone` 事件驱动；只改变展示层，不改变 RAG 事件协议。

## 服务层调整

扩展 `src/services/rag.ts` 和 `src/services/chat-service.ts`：

- `ChatOptions` 增加附件参数和附件状态回调。
- 增加创建远端会话函数，复用现有 API Key 和请求头逻辑。
- 增加临时附件上传、状态查询、删除函数，使用 `fetch` 和 `FormData`，不手动设置 multipart 的 `Content-Type`。
- `streamKnowledgeChat` 将 `attachment_ids` 写入请求体。
- 远端失败时继续使用本地降级答案，但要把附件失败原因显示给用户，不静默丢弃附件。
- 远端请求超时或页面离开时使用 `AbortController` 清理流和轮询。

## 状态与数据模型

`ChatMsg` 增加附件摘要字段，避免把 `File` 对象写入 localStorage：

- `attachments: { id: string; name: string; size: number; status: string }[]`
- 文件对象和轮询句柄只保存在组件内存中。
- 已完成会话的历史消息只保留附件名称、大小、状态和远端 ID。
- 重新加载历史会话时不自动重新上传文件；如果远端附件已过期，显示“附件已过期”。

## 响应式与可访问性

- 桌面端输入工作台最大宽度约 900px，始终贴近内容底部。
- 移动端输入工具栏允许换行，智能体和文件夹选择器改为全宽抽屉或底部弹层。
- 所有图标按钮提供 `aria-label` 和 tooltip。
- 上传、发送、停止和删除操作提供明确的禁用状态。
- 点阵动效在减少动效偏好下变为静态状态点。

## 验证标准

- 低权限用户看不到未授权智能体和知识库。
- 高权限用户默认选中全部授权知识库，取消后请求体准确变化。
- 智能体切换后下一次请求使用新 ID，历史消息不变化。
- 文档附件可上传、轮询、发送、删除；失败和解析超时有明确反馈。
- 无附件请求保持原有远端 RAG 和本地降级行为。
- SSE 流式回答、RAG 状态、引用抽屉和会话 localStorage 持久化继续可用。
- `npm run build` 和 `npx tsc --noEmit` 通过。
- 桌面端和 375px 移动端不出现横向滚动或输入区遮挡。
