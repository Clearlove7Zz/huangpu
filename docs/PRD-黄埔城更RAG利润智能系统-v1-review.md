# PRD 评审报告：黄埔城更 RAG 利润智能系统 PRD v2.0

**评审对象**：docs/PRD-黄埔城更RAG利润智能系统-v1.md ｜ **日期**：2026-08-31 ｜ **项目类型**：AI(RAG) + 企业级 + 立项方案类
**判定**：**不合格**（65/100 = A 机械 23/40 + B 内容 42/60）——无 Blocker，但低于 70 分合格线；修复 P1 后可复审。

## 一句话总评

这份 PRD 的骨架（验收格式、WBS、风险表）已达到企业级水准，但"负空间"全空着：没有非目标章节、全文零事实打标、性能指标无 baseline 结构，且 M3 验收依赖一份**已删除的外部文档**（对齐清单）——评审会上第一个被问"7 处是哪 7 处"就会卡住。

## P1（应修，修复后才能过合格线）

- [ ] **P1-1 "对齐清零"悬空引用——引用已删除的文档**
  - 原文：M3 DoD "react全面接管（对齐清零）"（L563）；FR-05 "补齐 7 处可编辑能力"（隐含）；AD-04 同源
  - 为什么：反模式 3 变体——依赖外部不存在的东西。《项目1-vs-项目2-对比与对齐计划》已在历史操作中删除，"7 处可编辑能力"清单随之丢失。验收条件指向一个查不到的清单 = QA 无法执行，评审会上必被问住。
  - 怎么改：把 7 处清单直接写进 FR-05 验收条件。示范：
    > **FR-05 验收条件**：以下 7 处可编辑能力全部完成——①证照表编辑 ②设计进度表编辑 ③成本 Tab 三表编辑 ④安全巡检表编辑 ⑤WBS 与里程碑编辑 ⑥现金流明细面板编辑 ⑦供应商默认编辑态。（[NEED: 从 git 历史恢复《对齐计划》原文核对清单完整性——前端工程师，M1 前]）

- [ ] **P1-2 全文零事实打标**
  - 原文：§13 "约¥5-6万"、"5-7人月"；§5.2 "7-8路×32K（保守）"
  - 为什么：违反共同原则 6（[data]/[hunch]/[assumption] 打标）。"¥5-6万"是网上街价估计（hunch），"5-7人月"是拍脑袋（hunch），"7-8路"是纸面推算（hunch）——读者无法分辨哪些有据可查。立项会上财务问"5-6万怎么来的"，答不上就丢分。
  - 怎么改：示范（预算表）：
    > | 机器1 GPU推理机 | ¥5-6万 [hunch: RTX 6000 Ada 街价 $6,800-8,500/卡 ×2 + 整机，待询价] |

- [ ] **P1-3 无独立"非目标"章节**
  - 原文：附录 C 系统边界表"不在本期范围：安全巡检AI（保留不动）/真实业务系统对接（BIM/供应链/广联达）/Wiki+GraphRAG（P2）/航拍多模态摘要（P2）/沙箱代码执行（M3切Cube）"
  - 为什么：反模式 10——范围没有护栏。非目标藏在附录里且每条没有"为什么不做"的理由，范围蔓延时（领导说"航拍摘要顺手做了吧"）没有挡箭牌。
  - 怎么改：正文 §3 之前加"非目标"节。示范：
    > ## 非目标
    > | 不做什么 | 为什么不做 |
    > |---|---|
    > | 安全巡检 AI 改造 | 已是真实 AI（YOLOv8 后端），改造无收益 |
    > | 航拍图多模态摘要 | 主模型多模态能力未验证，试点后评估（P2） |
    > | 真实业务系统对接（BIM/供应链/广联达） | 对方接口未开放，本期内无法联调 |

- [ ] **P1-4 企业级 gate：内容治理缺新鲜度与删除传播**
  - 原文：§5 有四道关和 owner（业务数据员/负责人），但无"台账多久更新一次"、"删除文档后向量索引/引擎台账如何同步清理"
  - 为什么：企业级 gate 要求 owner/新鲜度/删除传播 SLA 三件齐。台账过期后 AI 还在用旧利润率回答，比没有 AI 更危险。
  - 怎么改：§5.2 后加一条：
    > **数据新鲜度 SLA** [NEED: 业务部门确认更新频率]：台账更新周期 ≤X 天；超期数据在 AI 回答中标注"数据截至 YYYY-MM-DD"。**删除传播**：源文档删除后，对应 chunk 与向量索引 24h 内清理，引擎台账同步下线。

## 三视角速评

- 🎯 产品：问题陈述遮住后能复原（假 AI→真 RAG 清晰），但"现在商务部手动推演一次要多久"这类业务代价数据为零；P1 验收口径"内部试运行可用"不可测——试运行谁签字？跑什么算通过？

## 亮点（做对了的，保持）

- **验收格式业界标准**：FR 全部 Given-When-Then + 逐位比对的绝对验收标准（不允许"差不多"），QA 拿到即可写测试用例。
- **诚实列缺口**：§4.5 待业务确认项主动列出（基准利润率口径、成本系数 0.12 vs 0.22），没有藏争议。
- **WBS 到 task 级 + 关键路径分析**：M0-M3 拆到 M1.1/M2.3 粒度，标注串并行依赖和两条关键路径，排期可信度高。
- **最危险假设有探针**：R1（vLLM 架构支持）对应 A3 行动项"开发机先行验证"，失败退路明确（SGLang）。
