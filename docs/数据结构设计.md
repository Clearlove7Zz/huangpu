**口径说明**：本文定义平台所有持久化数据的归属、库表结构、字段与边界。标注【现状】的为已核实仓库/已落地结构（附来源）；标注【目标】的为随里程碑落地的设计，字段以 M1/M2 实现时为准；无依据的字段不臆造，以 `[NEED]` 标注待业务确认。

**一条铁律**：引擎算法常量与公式不属于数据库设计范围，仍以 `engine.mjs` / `engine-data.mjs` 为算法单源；数据库只存放**台账事实数据**与**基线快照**，不存放可由公式推导的结果（推演结果按需留痕，见 §4.4）。

## 1. 存储全景

| # | 存储 | 位置 | 归属 | 端口 | 存什么 | 谁可写 |
|---|---|---|---|---|---|---|
| 1 | 平台库 PostgreSQL | 应用服务器，独立容器 | 网关自有（WeKnora compose 之外） | 5433（规划） | 账号权限、业务台账、引擎基线、Token 用量、审计 | 后端网关；引擎 MCP（仅基线读取） |
| 2 | WeKnora 库 PostgreSQL 17（ParadeDB + pgvector） | WeKnora compose | WeKnora 拥有（不改表结构，仅配置/扩展列） | 5432（容器内） | 知识库、文档、分块、向量、智能体、MCP 服务配置、会话 | WeKnora app；网关不直写 |
| 3 | Neo4j 2025.10.1 | WeKnora compose | WeKnora 图谱能力拥有 | 7474 / 7687 | 实体/关系图谱 | WeKnora 图谱抽取任务 |
| 4 | Redis 7 | WeKnora compose | WeKnora | 6379 | asynq 任务队列、缓存、限流计数 | WeKnora app；网关额度计数（见 §6.3） |
| 5 | 审计 JSONL | 网关 `logs/gateway-audit.jsonl` | 网关 | 文件 | 登录/代理/对账裁决流水【现状】；M3 迁入平台库（见 §7） | 网关追加写 |
| 6 | 引擎数据模块 | `huangpu-gateway/lib/engine-data.mjs` | 引擎算法单源 | — | 红线常量、因子定义、预设情景 | 代码维护，不接受运行时改写 |

**平台库内部 schema 划分**（一个 PG 实例、三个 schema，职责隔离、备份粒度清晰）：

- `iam`：身份与权限（users / roles / user_role / login_audit / 会话映射）
- `biz`：业务台账与引擎基线（projects / baseline_snapshot / cashflow_monthly / cost_ledger / progress_evm / scenario_record / ingestion_task / sync_log）
- `ops`：运营与审计（maas_usage / quota_budget / gateway_audit / degradation_log）

**通用约定**：

- 主键：业务表统一 `id BIGSERIAL` 或 UUID（由网关生成，对外只暴露 UUID，避免序号枚举）；下文以 `id` 简称。
- 审计字段：所有业务表带 `created_at timestamptz default now()`、`updated_at timestamptz`、`created_by uuid`、`updated_by uuid`、`is_deleted boolean default false`（软删除，知识/台账不物理删除，保留追溯）。
- 金额单位：万元（与引擎、演示数据一致）；比率以小数存储（16.66% 存 `0.1666`）；月份键统一 `YYYY-MM`。
- 字符集 UTF-8；时间一律 UTC 存储、前端按本地时区展示。

## 2. 身份与权限（iam schema）

> 依据：2026-09-09 决策——用户账号库为网关自有的独立 PostgreSQL 容器，令牌载荷升级为 `{user_id, role, name, exp}`；demo 现状 7 组硬编码账号（`lib/auth.mjs`）。

### 2.1 users（用户）【目标，M2】

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | 网关签发 |
| login_name | varchar(64) unique | 登录名（工号或统一认证账号） |
| display_name | varchar(64) | 姓名（令牌 `name`） |
| role_code | varchar(32) | 角色码，外键 roles.code（与 `rbac.mjs` 六角色一致） |
| dept | varchar(64) | 部门（用于用量按部门归集） |
| status | varchar(16) | active / disabled |
| auth_source | varchar(16) | local / sso / wechat（手机端微信授权映射） |
| external_subject | varchar(128) | 统一认证/微信 openid 映射（`auth_source≠local` 时） |
| last_login_at | timestamptz | 最近登录 |
| 审计字段 | — | 见 §1 通用约定 |

初始化：M2 迁移时把 7 组演示账号（指挥长/商务部×2/外协/工程/安全/财务＋全权限测试账号）写入本表，测试账号仅在非生产环境保留。

### 2.2 roles（角色）与权限约束【目标，M2】

`roles`：`code PK`、`name`、`kb_keywords`（知识库白名单，`*` 表示全库）、`agent_whitelist`（智能体白名单/名称关键词）、`can_ask_profit boolean`、`is_fallback boolean`（最低权限兜底角色）。

权限真值以网关 `lib/rbac.mjs` 为准（六角色三约束：知识库白名单/智能体白名单/能否问利润）；本表是它的可管理化镜像，**运行时拦截仍以服务端代码/表共同判定，前端 `rbac.ts` 只做界面过滤**。修改角色约束须走管理员页（见《UI 与功能设计》§3.10）并留审计。

### 2.3 会话映射与登录审计

- `wechat_session`（手机端）：`id`、`user_id`、`openid`、`session_key_ref`（不存明文 session_key，仅存引用/哈希）、`gateway_token_jti`、`created_at`、`expires_at`。微信授权后换取网关 HMAC 令牌（12h），续期重写映射。
- `login_audit`：`id`、`user_id`、`login_name`、`client`（web/miniprogram/h5）、`ip`、`ua`、`result`（success/fail/disabled）、`reason`、`created_at`。

WeKnora 侧会话隔离：网关注入 `X-External-User-ID: <user_id>`，WeKnora 按该头隔离会话与记忆【现状能力，零改码，依据 `internal/types/session.go`、`internal/middleware/auth.go`】；user_id 同时落 WeKnora 会话记录（见 §5.6）。

## 3. 六库知识分类元数据（biz 层登记，内容在 WeKnora）

六库是 RBAC 白名单与知识入库的口径来源，物理文档/向量在 WeKnora 库；平台库只登记**目录级元数据与归属**，供台账页、权限页、入库流程引用。

`kb_catalog`【目标，M1】：

| 字段 | 说明 |
|---|---|
| code | 库代码：project / cost / cashflow / contract / rules / safety |
| name | 项目库 / 成本库 / 现金流库 / 合同库 / 规范库 / 安全库 |
| weknora_kb_id | WeKnora 知识库 ID（建库后回填，重建会变，需同步） |
| owner_dept | 责任部门（成本库→成本部，安全库→安全部，其余→工程部） |
| update_frequency | 更新频率（月/双周/周；Q4 待业务确认 SLA） |
| data_cutoff_date | 当前数据截止日期（AI 回答需标注，REQ-10） |
| embedding_model | 建库所用 Embedding 模型（换模型须重建向量索引） |

**删除传播**：WeKnora 知识库/文档删除受外键与异步任务约束（文档→分块→向量→图谱实体引用），平台侧不直删；文档生命周期管理走 WeKnora 界面/接口，`kb_catalog` 只登记不级联物理删除。

### 4.3 明细台账表

- `cashflow_monthly`：`project_id`、`month`、`inflow`、`outflow`、`net`、`balance`、`collection_rate`（回款率%）、`overdue_ar`（逾期应收）、`source`。支撑现金流红线、回款延迟因子与现金流台账页。
- `cost_ledger`：`project_id`、`month`、`cost_item`（钢筋/混凝土/分包/人工/机械/其他）、`budgeted`、`actual`、`variance`、`unit_price`、`consumption`、`source`。支撑成本台账、三算对比与因子（钢筋/混凝土/分包涨价）。
- `progress_evm`：`project_id`、`month`、`pv`、`ev`、`ac`、`spi`、`cpi`、`eac`、`vac`、`milestone_status`、`delay_days`（延误天数因子来源）、`source`。
- `quality_rectification`：`project_id`、`month`、`issue_count`、`estimated_cost`（质量整改费用因子）、`closed_count`、`status`。支撑安全质量页与质量整改因子。

各明细表均带通用审计字段；`source` 区分接入/人工，接入数据另挂 `sync_log_id` 可追溯批次。表为最小必要集合，M2 按真实台账字段对齐扩列 [NEED：业务提供现有台账表头]。

### 4.4 scenario_record（推演留痕，可选【目标 M2】）

利润问答经 `run_scenario` 时，按需记录：`id`、`project_id`、`user_id`、`session_id`、`factors_input jsonb`、`result_json`（SimResult：推演利润率/现金流/SPI/CPI/EAC/VAC/六红线判定/建议）、`engine_version`、`created_at`。

用途：复盘"当时为什么这么答"、评测集回归、领导追问留痕。**不作为引擎计算的输入**（引擎永远以基线快照＋当场因子实时算），避免结果反哺事实。是否全量记录或抽样记录由 M2 评审定（涉及存储与对话隐私）。

### 4.5 数据接入（报价 E-02）

- `ingestion_task`：`id`、`source_system`（甲方现有系统名/Excel 台账/接口）、`source_type`（db/api/file/manual）、`target_table`、`schedule_cron`、`owner`、`status`（planned/testing/active/paused）、`last_run_at`、`remark`。
- `sync_log`：`id`、`task_id`、`started_at`、`finished_at`、`rows_read`、`rows_written`、`rows_rejected`、`result`（success/fail/partial）、`error_detail`、`data_cutoff_month`。
- 接入分阶段（报价 E-02 按阶段计）：M2 先接 Excel/表格导入与人工录入闭环；M3 按甲方系统开放情况接接口/数据库，接入清单与字段映射随实施调研另册 [NEED：甲方现有系统清单与接口开放程度]。

## 5. WeKnora 侧数据（引用与扩展点，不拥有表结构）

以下为 WeKnora 自有表/能力，平台不改其结构，仅通过管理界面、配置与 API 使用；列出是为了明确数据流向与对账/图谱的落点。

### 5.1 知识库与文档（WeKnora 库）

- 知识库（knowledge base）：六库物理载体，租户 API key 可按 `KnowledgeBaseIDs` 限定范围【源码核实 `internal/types/tenant_api_key.go`】。
- 文档 documents：上传文件、解析状态（uploaded→processing→parsed→indexed/failed）、所属知识库、doc_type、项目/月份等元数据（供检索过滤 `{project_id, doc_type, 月份}`）。
- 分块 chunks 与向量：ParadeDB/pgvector 存储，BM25＋向量混合检索（RRF 0.7/0.3），rerank top_k=30、最终 top_k=5、threshold=0.3【配置 `config/config.yaml`】。Embedding 维度建库前定死（bge-m3 为 1024 维；若用 MaaS embedding 以其维度为准，**换模型必须重建索引**）。

### 5.2 智能体（agents）

六角色智能体（指挥长/商务/工程/安全/财务/外协）共用 prompt 模板，差异在知识库绑定与工具；基于 progressive_rag_agent 追加角色定义、工具指引、报告格式、拒答规则。智能体 ID 在知识库重建后会漂移，故网关白名单对自定义智能体按名称关键词匹配（架构 §4.3）。平台化后新增业务助手（商务/工程/安全/资料等域，报价 B-03）同样登记于此，见 PRD §3.9。

### 5.3 MCP 服务配置（mcp_services）【现状表】

WeKnora 表 `mcp_services`（`migrations/000001_agent.up.sql` L263-280）：`transport_type`、`url`、`headers`、`auth_config`（JSONB）。引擎 MCP 以 http-streamable 注册：`http://host.docker.internal:18095/mcp`，`X-API-Key` 自鉴权。图谱工具、后续业务系统工具同表登记。

### 5.4 知识图谱（Neo4j）

- 节点标签（首版）：`Project`（项目/地块）、`Company`（甲方/分包/供应商）、`Person`（责任人）、`Contract`（合同）、`Document`（制度/方案/台账文件）、`Risk`（风险点）、`Milestone`（节点）。
- 关系类型：`BELONGS_TO`、`SIGNS`（签约）、`RESPONSIBLE_FOR`、`REFERENCES`（文档引用）、`CAUSES`（风险致因）、`DEPENDS_ON`（节点依赖）、`MENTIONS`（文档提及实体，回链 chunk_id 溯源）。
- 每个实体保留 `source_doc_id` / `source_chunk_id` 溯源到原文；图谱检索作为第 5 类数据工具调用计入网关对账白名单（架构 §4.2）。
- 图谱本体（标签/关系/属性）M1 随六库抽样文档验证后冻结，抽取由 WeKnora 图谱任务写入，平台不直写 Neo4j。

### 5.5 Redis / asynq

文档解析、嵌入、图谱抽取为 asynq 异步任务；Redis 另承载网关侧**额度滑动窗口计数**（§6.3，短时突发限流用，持久账单以 `maas_usage` 为准）。

### 5.6 会话与用户隔离

WeKnora 会话（sessions/消息/工具调用记录）经 `X-External-User-ID` 携带的 user_id 隔离与归属；会话内 SSE 八类事件（answer/thinking/tool_call/references 等）是网关审计与对账的原始来源。会话保留期与删除（用户被遗忘权）遵循 WeKnora 能力 + 甲方制度 [NEED：保留期限]。

## 6. Token 计量与额度（ops schema，对应报价 C-01/C-03）

### 6.1 maas_usage（用量流水）【目标，M0 埋点】

网关在 SSE 旁路解析 WeKnora/MaaS 回执的 usage，每次模型调用一条：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigserial PK | |
| user_id | uuid | 调用方（平台库 iam） |
| role_code | varchar(32) | 冗余角色，便于归集 |
| dept | varchar(64) | 部门 |
| agent_id / kb_scope | varchar | 助手/智能体与知识库范围 |
| session_id | varchar(64) | WeKnora 会话 |
| model | varchar(64) | 实际模型标识（MaaS 回执） |
| capability | varchar(16) | chat / embedding / rerank / doc_ocr |
| prompt_tokens | integer | 入（含系统提示/检索片段/历史） |
| completion_tokens | integer | 出 |
| total_tokens | integer | 合计 |
| status | varchar(16) | ok / degraded / blocked（熔断拦截） |
| created_at | timestamptz | 调用时间 |

索引：`(created_at)`、`(user_id, created_at)`、`(dept, created_at)`；月度/部门汇总用物化视图或定时聚合（M2 定）。

### 6.2 quota_budget（额度预算）

| 字段 | 说明 |
|---|---|
| scope | year / month / dept / user |
| period | 如 2026 / 2026-10 / 部门码 / 用户 id |
| token_quota | 该周期额度（年度首年约 10 亿，来源合同 C-01；按月切分建议值由 M0 实测后定） |
| warn_70 / warn_90 | 阈值动作是否已触发（避免重复告警） |
| over_action | 熔断策略：fuse_readonly（默认，只读+引擎）/ approve_extend（审批续通） |
| approver / approved_at / extra_terms | 续通审批人与超额单价条款（合同明确后填）[NEED：超额单价] |

### 6.3 计数与熔断落点

- 持久账单：`maas_usage` 聚合，权威口径；
- 短时突发：Redis 滑动窗口（每分钟/每用户调用数与 Token），防失控批量调用；
- 熔断：网关在请求前查周期累计，达 100% 且无续通审批 → 不转发生成式请求，转 ③' 级降级（架构 §4.5），返回只读检索＋引擎数值；
- 阈值动作（70/90/100%）与用户可见状态见《UI 与功能设计》§3.9。
